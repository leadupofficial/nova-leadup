## 3. What Fails

### BLOCKER 1: `@nova/types` build failure (CRITICAL — blocks everything)

**Error:**
```
@nova/types:build: tsconfig.json(2,13): error TS6053: File '@nova/config/tsconfig/base.json' not found.
```

**Root cause:** `packages/types/tsconfig.json` extends `@nova/config/tsconfig/base.json`. The `@nova/config` package exists at `packages/config/` but is **not listed as a dependency** in `packages/types/package.json`. It has no `dependencies` at all — only `devDependencies: { typescript }`.

**Affected:** Any task that builds `@nova/types` (build, test, typecheck cascades). This blocks the monorepo-level build and test commands.

**Fix needed:** Add `@nova/config: workspace:*` to `packages/types/package.json` dependencies (or devDependencies since it's a TS config package).

### BLOCKER 2: `@nova/policy` build failure (HIGH)

**Error 1 — Missing dependency:**
```
@nova/policy:build: src/rate-limiter.ts(8,23): error TS2307: Cannot find module 'ioredis' or its corresponding type declarations.
```

`ioredis` is not listed in `packages/policy/package.json` at all, but `rate-limiter.ts` imports it directly.

**Error 2 — Async code bug:**
```
@nova/policy:build: src/index.ts(334,20): error TS2339: Property 'allowed' does not exist on type 'Promise<RateLimitResult>'.
```

Line 334 calls `this.rateLimiter.check(...)` but doesn't `await` it, so `rateResult` is a `Promise<RateLimitResult>` instead of `RateLimitResult`.

**Fix needed:**
1. Add `ioredis: ^5.x` to `packages/policy/package.json` dependencies
2. Add `await` before `this.rateLimiter.check(...)` in `src/index.ts:330-333`

### BLOCKER 3: `pnpm run build` fails (consequence of Blockers 1 & 2)

```
Failed: @nova/policy#build, @nova/types#build
Tasks: 4 successful, 14 total
```

### BLOCKER 4: `pnpm test` fails (consequence of Blocker 1)

```
Failed: @nova/types#build
Tasks: 3 successful, 18 total
```

Tests that depend on `@nova/types` cannot run.

## Summary

The NOVA monorepo has a **well-structured architecture** with clear separation between apps, services, and shared packages. The tech stack is modern (Express, Next.js, Flutter, Drizzle, BullMQ, Anthropic SDK, Socket.io).

**The build is broken by two trivial missing dependencies and one async bug** — all fixable in minutes. Once B1 and B2 are resolved, `pnpm run build` and `pnpm test` should pass.

**The mobile app is Flutter** and its Android build, auth flow, wake word and Firebase
integration were re-verified on 2026-09-18. The authoritative operational detail lives
with the code rather than in this file: `apps/mobile/tools/wakeword/README.md`,
`apps/mobile/tools/firebase/activate.sh`, and `services/api/scripts/verify-auth.py`.
The Expo sources still in `apps/mobile` are dead weight and should be removed.

**There is no payment integration** and no deployment configuration beyond a single Dockerfile.
